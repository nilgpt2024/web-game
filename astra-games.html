🤖 AI Games Built With GPT-6 Astra

110 browser builds from the GPT-6 Astra generation, collected from the public awesome-gpt-6-astra directory. Where the creator published build notes, the game page shows them: the model, what the model actually did, the stack, and the original release so you can compare it with the copy here.

What this collection is

These are small games made in a browser tab rather than a studio pipeline. Most are a single HTML file with JavaScript, Canvas or Three.js, assets generated in code, and no download step at all: open the page and the game is already running. The point of interest is not only that a model wrote them, but that you can read, on each page, which parts the model produced and which parts a human steered.

The directory this collection comes from was assembled by volunteers who asked creators what they used. That is why the notes vary in depth: some creators wrote a paragraph about iterating on prompts and playtesting, others simply said "GPT-6 Astra" and moved on. We publish what exists rather than inventing the rest.

What the build notes usually say

A recurring pattern across the pages is that nobody shipped on the first prompt. Creators describe a loop: ask for a mechanic, play it, notice the collision or the difficulty curve is wrong, ask again, and repeat until the loop feels fair. The model is fast at producing a playable draft and poor at judging whether it is fun, which is the part the human keeps.

A second pattern is scope discipline. The builds that hold up are usually one idea carried through: a dodge game, a kart race, a tower defence, a short narrative room. Ambitious multi-system games in this set tend to be the ones with a long "still a work in progress" note attached.

A third is that the visual style is cheap by design. Procedurally generated terrain, flat-shaded primitives, or a hand-picked colour palette do the heavy lifting, because a model cannot reliably produce bespoke art assets. When a game looks good here, it is usually because the constraint was chosen well, not because the model painted a masterpiece.

Where to start

If you have two minutes, pick a reflex game: the arcade-style dodgers and shooters in this set load instantly and end quickly. If you want something to sit with, choose one with a longer build note — those tend to be the projects the creator cared about, and the page will tell you what to expect before you commit.

On a phone, favour tap and drag titles; on a desktop, the keyboard-driven ones are sharper. A few builds need WebGL 2 or WebGPU, and the game page says so in its play check line rather than letting you find out after a blank screen.

What we changed and what we did not

We mirror the builds so the games open here without a redirect, and we add the play-check result we actually observed. We do not rewrite the creators' claims, do not add screenshots that are not theirs, and do not relabel a game as AI-made when the creator has not said so. If a link to an original release is dead, the page still names the creator so the trail is not lost.

How the pages are built

Each entry has the same skeleton — model, creator, stack, original release, what the model did, play check, catalogue credit — followed by the same related-games block as the rest of the site. That consistency is deliberate: it makes a claim checkable in seconds, and it means a page with a thin note is visibly thin instead of padded with generic prose.
